Dokumentasi Pengembangan Software

Blueprint awal untuk web cek tagihan dan cara pembayaran mahasiswa UT yang berafiliasi dengan SALUT Awwabin. Dokumen ini dirancang agar mudah dibaca oleh pengelola, admin, developer, dan reviewer.

Ringkasan

Status Planning
Target stack VPS + SQLite
Dokumen sumber 17 MD
Kontrol utama Privacy first

MVP berfokus pada pencarian tagihan, instruksi pembayaran, admin dashboard, import data, audit log, dan hardening dasar. NIM tidak diperlakukan sebagai rahasia kuat, sehingga lookup publik direkomendasikan memakai nama sebagai pasangan NIM.

Scope MVP

Public lookup nama plus NIM, hasil dimasking, rate limit.
Tagihan Periode, jenis tagihan, nominal, status, BRIVA, dan instruksi.
Cara bayar BRIVA dan instruksi pembayaran dari workbook sumber.
Admin dashboard Login, preview workbook XLSX, dan commit import.
Import data Workbook XLSX dengan preview perubahan, validasi kritis, dan konfirmasi nominal atau BRIVA.
Auditability Audit log untuk login, import, dan perubahan data penting.

Requirement Utama

ID Requirement Prioritas Acceptance Criteria
FR-001 Mahasiswa dapat membuka halaman cek tagihan tanpa login. Must Halaman publik tersedia dan dapat diakses.
FR-003 Sistem meminta nama sebagai pasangan NIM. Must Form memiliki nama mahasiswa sesuai konfigurasi.
FR-004 Sistem menampilkan tagihan ditemukan. Must Hasil memuat periode, jenis, nominal, status, BRIVA, dan instruksi.
FR-008 Admin dapat login. Must Admin berhasil masuk menggunakan Internal Auth.
FR-009 Admin dapat upload workbook XLSX tagihan. Must Preview membedakan data baru, tidak berubah, dan perubahan sensitif sebelum commit.

Arsitektur

Aplikasi menggunakan Frontend statis dan Backend Python di VPS. SQLite dipakai sebagai database file, Internal Auth menangani login admin, dan Filesystem VPS menyimpan file upload opsional. Browser tidak membaca tabel sensitif secara langsung.

Komponen Tanggung Jawab Platform
Public Web Form cek tagihan dan halaman hasil. VPS
Admin Web Dashboard pengelolaan data. VPS
API Layer Validasi, rate limit, query server-side, masking. Python service
Database Mahasiswa, tagihan, pembayaran, audit, konfigurasi. SQLite
Auth Login admin dan session management. Internal Auth

Database

Tabel Fungsi Catatan Penting
students Data mahasiswa. NIM unique, nama dimasking pada response publik.
bills Data tagihan. Rilis ini mengimpor status unpaid.
import_issues Warning dan data tidak lengkap dari workbook. Sheet Data Belum Lengkap tidak tampil publik.
admin_users dan admin_sessions Identitas admin dan session login. Token session disimpan dalam bentuk hash.
lookup_logs Log pencarian publik. Simpan hash NIM/IP, bukan data mentah.
audit_logs Audit perubahan admin. Mencatat login, logout, preview, dan commit import.

API Contract

Endpoint Method Tujuan Auth
/api/lookup POST Cari tagihan berdasarkan nama dan NIM. Public + rate limit
/api/admin/login POST Login admin dan membuat session. Admin
/api/admin/me GET Mengambil profil session admin aktif. Admin
/api/admin/logout POST Menghapus session admin aktif. Admin
/api/admin/import/preview POST Validasi file import tanpa commit. Admin
/api/admin/import/commit POST Simpan data import ke database. Admin

Security dan Privacy

ID Kontrol Acceptance Criteria
SEC-001 Secret tidak boleh berada di repository. .env* diignore kecuali template aman.
SEC-002 Public lookup memakai verifikasi tambahan. Lookup tanpa verifikasi ditolak.
SEC-003 Response publik harus dimasking. Nama tidak pernah tampil penuh.
SEC-004 API admin memvalidasi role. Role tidak cukup ditolak 403.
SEC-005 Audit log wajib untuk perubahan penting. Create/update/delete/import menghasilkan audit log.

Admin dan Operasional

  1. Admin menyiapkan workbook XLSX dengan sheet yang disetujui.
  2. Admin login ke dashboard.
  3. Admin upload file tagihan.
  4. Sistem menampilkan preview dan error per baris.
  5. Admin memperbaiki data bila ada error kritis.
  6. Admin commit import hanya saat tidak ada baris kritis dan perubahan nominal/BRIVA telah disetujui.
  7. Sistem menyimpan data tagihan, issue import, dan audit log.
